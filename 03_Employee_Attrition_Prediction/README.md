# Employee Attrition Prediction

## Overview
This project uses machine learning to predict whether an employee may leave an organization. It uses the IBM HR Analytics Employee Attrition dataset and a Random Forest classifier.

## Objectives
- Explore employee data and identify patterns associated with attrition.
- Prepare categorical and numerical features for modelling.
- Train a classification model to predict employee attrition.
- Evaluate the model using accuracy, precision, recall, F1-score, and a confusion matrix.

## Dataset
- **Dataset:** IBM HR Analytics Employee Attrition
- **Rows:** 1,470
- **Columns:** 35
- **Target:** `Attrition` (Yes/No)
- Check the notebook for the exact dataset-loading method and source details.

## Technologies
- Python
- Pandas and NumPy
- Scikit-learn
- Matplotlib and Seaborn
- Jupyter Notebook / Google Colab

## Methodology
1. Load and inspect the HR analytics dataset.
2. Separate the target label from the input features.
3. Preprocess the features, including encoding categorical variables.
4. Split the data into training and testing sets.
5. Select features using a statistical feature-selection method.
6. Train a Random Forest classifier.
7. Evaluate predictions with classification metrics and a confusion matrix.

## Key Results
The notebook's evaluated model reported:
- **Accuracy:** 83.33%
- **Precision for attrition (class 1):** 46.15%
- **Recall for attrition (class 1):** 25.53%
- **F1-score for attrition (class 1):** 32.88%

Confusion matrix (actual rows, predicted columns; Stay/Leave order):
```text
                 Predicted Stay  Predicted Leave
Actual Stay              233               14
Actual Leave              35               12
```

Accuracy alone does not describe performance on the minority attrition class. In these results, recall is relatively low, meaning the model misses many employees who leave. This is an important limitation to consider when interpreting predictions.

## Limitations and Responsible Use
- The target class is imbalanced, so accuracy can be misleading when used alone.
- The model may miss employees who leave; predictions should not be treated as certain outcomes.
- HR predictions can affect people. Use them only as decision-support signals, assess fairness and privacy, and never use a model score as the sole basis for employment decisions.
- Results depend on the dataset, preprocessing, split, and model settings.

## Possible Improvements
- Tune the decision threshold and model hyperparameters.
- Compare class-weighting and resampling strategies.
- Inspect precision-recall trade-offs and calibration.
- Evaluate fairness across relevant employee groups where appropriate and lawful.
